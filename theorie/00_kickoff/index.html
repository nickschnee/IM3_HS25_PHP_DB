Was eine Data-Story ausmacht

Daten

Zahlen, die eine Frage wirklich beantworten können.

Zeit

Ein Zeitraum, über den sich etwas verändert.

Darstellung

Eine Grafik, in der man die Veränderung sieht.

Einbettung

Text, der sagt, warum das jemanden angeht.

Die ersten beiden Teile beschafft ihr, die letzten beiden gestaltet ihr.

Diese vier Begriffe an der Wandtafel mit den Antworten aus der Galerie abgleichen. Meist fehlt der Klasse der Punkt Zeit – genau der macht aus einer Tabelle eine Geschichte.

Was ihr dafür bauen werdet

Hinten
  • Eine Datenquelle, die euch Zahlen liefert
  • Ein Skript, das diese Zahlen säubert
  • Eine Datenbank, die sie behält
  • Ein Endpunkt, der sie als JSON ausgibt
Vorne
  • HTML, CSS und JavaScript wie in den bisherigen Kursen
  • Chart.js für die Grafik
  • Text, Titel und Quellenangaben

Neu ist für die meisten nur die linke Spalte.

Beruhigend formulieren: Die rechte Spalte koennt ihr bereits. PHP und Datenbank sind das Neue, und wir gehen sie in kleinen Schritten durch.

Jeder Schritt ist eine eigene PHP-Datei mit genau einer Aufgabe.

Extract, Transform und Load heissen überall so und werden zu ETL abgekürzt.

Unload ist unser eigener Name für den Schritt danach.

Diese Kette kommt in jedem weiteren Foliensatz als «Wo wir stehen» wieder. Hier bewusst nur benennen, nicht erklaeren – jeder Schritt bekommt spaeter seinen eigenen Tag.

Wer im Team was macht

Backend zu zweit

Ihr holt die Daten, säubert sie und speichert sie in der Datenbank.

Am Ende liefert ihr einen JSON-Endpunkt aus.

Frontend zu zweit

Ihr baut die Story und die Grafik mit Chart.js.

Ihr startet mit erfundenen Daten und wechselt später auf den echten Endpunkt.

Damit das zusammenpasst, einigt ihr euch früh auf die Feldnamen der JSON-Ausgabe.

Diese Vereinbarung heisst im Kurs Datenvertrag. Hier nur ankuendigen; festgehalten wird sie erst, wenn die ersten echten Daten da sind. Wichtig: Beide Zweierteams bleiben fuer das Ganze verantwortlich.

Für euer Projekt zählen vor allem die ersten beiden.

Die Reihenfolge ist gleichzeitig eine Rangfolge: je weiter rechts, desto mehr Aufwand und desto unsicherer die Quelle.
Datensatz

Eine Datei, die schon jemand gefüllt hat

So kommt ein Datensatz meistens daher:

  • Als CSV, JSON oder Excel-Datei
  • Mit vielen Spalten, die ihr nicht alle braucht
  • Mit sehr vielen Zeilen
  • Über einen langen Zeitraum hinweg erhoben

Und so verhält er sich:

  • Er ändert sich nicht mehr
  • Er ist oft nicht aktuell
  • Er ist genau deshalb verlässlich

Ein Datensatz ist für ein Kursprojekt fast immer die ruhigere Wahl.

Hier gegen die verbreitete Erwartung arbeiten, ein Projekt brauche Live-Daten. Ein historischer Datensatz ist am Marktstand nicht langweilig, sondern schlicht da.
Datensatz

Ein langer Zeitraum macht Muster sichtbar

Zwei Muster in einer Grafik: Die Zahl steigt ueber die Jahre, und innerhalb jedes Jahres wiederholt sich derselbe Sommerausschlag. Beides sieht man nur, weil die Reihe so lang ist.
Datensatz

Daten müssen nicht von einer Behörde kommen

Eigenes Beispiel und guter Ideengeber fuer die Themenboerse spaeter: Auch selbst erhobene oder exportierte Daten sind ein Datensatz. Man sieht Beziehungen anfangen und aufhoeren.

API

Eine Adresse, die Daten zurückgibt

Was eine API ausmacht:

  • Ihr ruft eine URL auf und bekommt Daten statt einer Webseite
  • Die Antwort ist strukturiert, meistens als JSON
  • Die Daten sind aktuell

Womit ihr rechnen müsst:

  • Es gibt immer eine Obergrenze an Abfragen
  • Manche Anbieter verlangen eine Kreditkarte
  • Die Dokumentation ist mal gut und mal grauenhaft

Eine API liefert meist nur den aktuellen Wert – die Geschichte entsteht erst, wenn ihr selbst sammelt.

Genau das macht 1kwh.ch: Swissgrid gibt nur den Moment her, gesammelt wird selbst. Wer eine API waehlt, muss frueh anfangen zu sammeln.

Reverse Engineering

Die versteckte Datenquelle einer Website

Viele Websites laden ihre Inhalte selbst als JSON nach.

  • Im Netzwerk-Tab des Browsers seht ihr jede dieser Anfragen
  • Findet ihr die richtige, habt ihr die Daten direkt
  • Grosse Anbieter sichern ihre internen Schnittstellen dagegen ab

Diese Adressen sind nicht dokumentiert und können jederzeit verschwinden.

Rechtlich und praktisch heikel: keine Zusicherung, keine Dokumentation, keine Stabilitaet. Als Projektgrundlage nur mit gespeichertem Datenstand als Rueckfallebene.
Reverse Engineering

Was ein Radiosender wirklich spielt

Gute Ideenquelle fuer Projekte: Wer laeuft wie oft, zu welcher Tageszeit, in welchem Jahrzehnt erschienen. Aus so einer Tabelle wird ueber Wochen gesammelt eine echte Geschichte.

Webscraping

Wenn es gar keine Datenquelle gibt

Dann liest man die Website selbst aus und schneidet die Werte aus dem HTML.

  • Mit cURL in PHP oder mit fetch in JavaScript
  • Bei Seiten, die sich erst im Browser aufbauen, mit Puppeteer oder Selenium
  • Bei grossen Anbietern scheitert es meist an einer Schutzschicht

Ändert die Website ihr Layout, ist euer Skript kaputt.

Hier kann der Hinweis auf Bahn-Mining von David Kriesel fallen: ein Vortrag darueber, wie aus jahrelang gesammelten Fahrplandaten eine Geschichte ueber Verspaetungen wird.

Webscraping

Wie das Internet darüber denkt

Wer eine API benutzt, hält sich an Regeln, Kontingente und Nutzungsbedingungen.

Wer scrapt, hält sich an nichts – und fliegt dafür irgendwann raus.

Für euer Projekt gilt: nehmt die API, wenn es eine gibt.

Bewusst als Auflockerung. Danach ernst werden: Scraping erzeugt Last auf fremden Servern und ist je nach Nutzungsbedingungen nicht erlaubt.

Euer Projekt

Vier Personen, eine Frage, ein Datensatz, eine Grafik.

Der Auftrag in einem Satz

Ihr beantwortet eine Frage mit Daten, die ihr selbst beschafft, gespeichert und sichtbar gemacht habt.

Bewusst ohne Themenvorgabe. Das Thema entsteht gleich in der Themenboerse. Die Frage selbst wird erst spaeter scharf formuliert.

Woran ihr euch halten solltet

Eine Datenquelle

Nicht drei, auch wenn es verlockend klingt.

Ein kleines Datenmodell

Eine oder zwei Tabellen reichen völlig.

Ein JSON-Endpunkt

Er versorgt euer Frontend mit allem Nötigen.

Mindestens eine Grafik

Sie muss eure Frage beantworten, nicht beeindrucken.

Erfahrungsgemaess scheitern Projekte an zu grossen Plaenen, nie an zu kleinen. Diese vier Grenzen sind eine Hilfe, keine Strafe.
